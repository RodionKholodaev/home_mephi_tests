# home_mephi_tests

UI-автотесты на Java для личного кабинета МИФИ [home.mephi.ru](https://home.mephi.ru) и сервера входа auth.mephi.ru.

## Зачем этот проект

Учебный проект. Владелец проекта готовится к позиции QA-автоматизатора в Сбербанке: там тесты пишут на Java и Selenium. Цель — освоить стек и подходы, которые используют в промышленной автоматизации. Поэтому:

- решения выбираем «как в команде банка», а не «как проще»;
- объясняем по-русски и простым языком: владелец проекта только учится Java и автотестам;
- при правках объясняем, **почему** сделано именно так, а не только что изменилось.

## Стек

- Java 21, Maven
- Selenium 4 (именно Selenium, **не** Selenide: так пишут в целевой команде)
- JUnit 5 (включая `@ParameterizedTest`)
- Allure 2 (отчёты, `@Step`, скриншоты при падении) + AspectJ-агент в surefire
- dotenv-java: логин и пароль берутся из `.env`

## Команды

```
mvn clean test                    # все тесты
mvn clean test -Dheadless=true    # без окна браузера
mvn test -Dtest=AuthTest#emptyFormIsNotSubmitted   # один тест
mvn allure:serve                  # открыть отчёт по последнему прогону (Ctrl+C - остановить)
```

Окружение: JDK 21 (Temurin) задан в `JAVA_HOME`, Maven 3.9.16 лежит в `%USERPROFILE%\tools\apache-maven-3.9.16`. Если в текущей консоли `mvn` не находится, обнови `PATH` из системных переменных.

## Структура

```
src/test/java/.../homemephi/
  core/    Config (адреса, таймаут, .env), DriverFactory (настройки Chrome),
           FailureAttachments (скриншот/URL/HTML в Allure при падении)
  pages/   BasePage (обёртки с ожиданиями) и Page Object'ы: StartPage, LoginPage, ProfilePage
  tests/   BaseTest (браузер на каждый тест), AuthTest
src/test/resources/allure.properties  - результаты Allure в target/allure-results
```

## Подходы и почему они такие

- **Page Object.** Локаторы и действия живут в классах страниц, тесты читаются как сценарий. Если поменяется вёрстка, правка нужна в одном месте.
- **Проверки только в тестах.** Страница возвращает данные (`getErrorText()`), а `assert` пишет тест. Так страницу можно переиспользовать для любых проверок.
- **Конструктор страницы ждёт её загрузки,** а методы возвращают следующую страницу (`clickLogin()` возвращает `LoginPage`). Тест не может «проскочить» вперёд, пока страница не открылась.
- **Только явные ожидания** через `WebDriverWait` в `BasePage`. Никаких `Thread.sleep` и implicit wait: они делают тесты медленными и нестабильными.
- **Локаторы:** в приоритете `id` и `name`, затем CSS. По тексту не ищем, потому что текст меняют чаще вёрстки.
- **Свежий браузер на каждый тест:** тесты не зависят друг от друга и от порядка запуска.
- **Allure:** `@Step` ставим на публичные методы страниц, а не на низкоуровневые обёртки `BasePage` (иначе отчёт превращается в шум). Тестовые классы размечаем `@Epic` / `@Feature` / `@Story`.
- **Безопасность данных:** пароль в шагах помечается `@Param(mode = Parameter.Mode.MASKED)`, `WebDriver` — `HIDDEN`. `.env` не коммитится. В негативных тестах используем выдуманный логин, чтобы не заблокировать настоящую учётку.
- **Комментарии** объясняют *почему* (как про `stalenessOf` в `LoginPage`), а не пересказывают синтаксис Java.
